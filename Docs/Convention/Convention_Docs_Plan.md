# 컨벤션 문서 작성 계획


## 코드 스타일

> 교본에서 제시된 표기법에 따라 코드를 작성합니다.

### 변수

`변수명`은 	`camelCase` - 첫 단어는 소문자, 이후 단어는 대문자로 시작

`클래스명`은 `PascalCase` - 모든 단어를 대문자로 시작



| **대상**             | **표기법**                               | **예시**              |
|--------------------|---------------------------------------|-------------------------|
| **지역 변수**          | camelCase - 첫 단어는 소문자, 이후 단어는 대문자로 시작 | playerLevel, currentHp  |
| **클래스·형식 이름**      | PascalCase - 모든 단어를 대문자로 시작           | PlayerController        |
| **외부에 공개하는 멤버**    | PascalCase                            | MaxHealth               |
| **클래스 내부에만 쓰는 필드** | 밑줄 + camelCase                        | _currentHealth          |
| **상수**             | 모두 대문자, 단어 사이는 밑줄                     | MAX_LEVEL               |




> 프로퍼티 설정하는 경우, private 설정하는 경우 작성하기 



제한자를 private 기본값으로한다.
외부에서 필요한 경우 protected, 
더 정보가 필요하면 프로퍼티로, 
추가로 더 정보가 필요한 경우 public을 사용하는 방식으로

최대한 public 사용을 지양한다.

## 하루 작업 루틴

Google Spreadsheet 페이지 작업 일지 양식에 따라 추가하기

1. 오늘 한 작업
2. (있으면)막힌 부분
3. 내일 할 작업
4. 남은 작업
5. 오늘 진행한 커밋 // 강사님께 확인해보기
6. 위 내용을 하루 마무리 PR로 작성

커밋과 PR은 드롭다운 형식으로 진행중/완료/시작 전 등 진행상태를 업데이트한다.

## 기본 PR 양식 

PR 제목은 본인 브랜치 이름 작성할 때 작업 내용을 적는 것으로 한다.

- 어떤 일을 했는지?
- 왜 했는지?
- 확인 필요한 사항은 어떤건지?

	ㄴ>@언급 으로 확인 필요한 사람 호출하기
		플레이어 개발자 : @몬스터 @터렛 PR 확인좀

```
무엇을 했냐 (연관된 스크립트가 무엇이 있는지)

왜 했냐

확인한 것 (실행했는지, 에러없는지, 관계 없는 파일이 같이 안 들어갔는지, 빈 파일이 들어갔으면 내가 그 씬의 소유자입니다)

화면 (사용 방법 : 팀원들이 사용할 코드, 각 메서드의 의미 및 사용 방법 작성)

리뷰어에게 (전달할 특이사항)

```
