# TEAM 탕수육 찍먹파 Ground Rule

> ## [★★★ 기본 규칙(강사님 강조 사항) ★★★]
> - 남이 사용중인 씬 함부러 사용하면 뒤짐
> - 프리팹 마음대로 사용하면 뒤짐
> - meta 파일 건드리면 뒤짐


- 일일회의 일정
- 문서화 범위 (회의록, 기술문서, 일일 작업일지 등)

추후 Repository 개설 시 문서 폴더에 적재


## 시간과 소통

0. Slack으로 소통 진행, `Github 알림 채널`과 `소통 채널` 사용 

1. 일정 변경의 경우 **반드시** 미리 Slack에 전달하기
- 팀장님 언급추가 (ex: 일정 문제 있습니다 `@팀장님`)

2. Slack 질문에 대한 답변은 `댓글달기` 사용하기

3. 내용을 확인한 경우 메세지 내에 초록색 체크표시로 확인했음을 알리기

4. 작업 일지 매일 반드시 작성할 것

5. 작업 안된 부분이 있다면 PM에게 언급당할 수 있음


## 작업이 막혔을 때

1. 웹 검색 해보기

2. slack에 막힌 부분 아래 작성 방법에 따라 팀원에게 질문하고 토의해보기 (아는 부분 서로 공유해주기)

2.1 작성 방법 :

어떤 작업을 진행하려했고
어떤 부분에서 막혔는지
에러 메세지 내용과 에러 코드 위치
원하는 결과는 어떤 식으로 되는지


3. 안되면 팀장님께 물어보기

4. 상의해보고 안되는 부분 강사님께 질문




## 구현기능 리뷰 절차

1. Pull Request 할 때 팀장 및 팀원들 전원 변경 파일 및 코드 점검

2. 본인 업무와 관련된 부분 or 이해가 안되는 부분 review 작성하기
2-1. review 작성은 일반적으로 comment로 설정하여 작성, 반드시 고쳐야할 부분들은 Request changes로 설정하여 review 작성할 것

3. Issue 에는 본인 작업 branch에서 발생한 문제, 통합 과정에서 발생한 버그들을 작성방법에 맞게 작성
3-1. Issue가 해결이 된 경우 해결 완료 처리진행할 것
